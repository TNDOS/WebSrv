写一个 TNDDOS 程序Writing a TNDDOS program

TNX 程序是一个普通的 x86-64 ELF，由 tnxpack 转成 TNX 格式， 由内核加载到程序窗口里跑。你要写的东西只有两个：tnx_main() 和调用 API 的代码。 A TNX program is an ordinary x86-64 ELF, converted to TNX by tnxpack and loaded into the program window by the kernel. All you write is tnx_main() plus whatever API calls you need.

最小程序The smallest program

#include "tndrt.h" int tnx_main(void) { tnd_printf("hello from %s\n", "a TNX program"); return 0; }

入口是 tnx_main，不带参数，返回 int。 真正的入口桩 tnx_entry 在 SDK 的 lib/tndrt.c 里 —— 它把加载器传进来的 API 表存好再调你的 tnx_main。 所以程序里永远只写 tnd_xxx(...)，不需要知道 API 表从哪来。 The entry point is tnx_main, it takes no arguments and returns int. The real entry stub tnx_entry lives in the SDK at lib/tndrt.c: it stores the API table handed over by the loader and then calls your tnx_main. That is why a program only ever writes tnd_xxx(...) and never needs to know where the table came from.

编译Building it

cd repos\TNDOS-SDK tools\build-tnx.ps1 -Source examples\hello\hello.c -Out build\HELLO.TNX

脚本把三段串起来，TNX 不需要自己的编译器： The script chains three steps; TNX does not need a compiler of its own:

clang -> .o -> ld.lld -> .elf -> tnxpack -> .TNX

编出来的 .TNX 丢到 ESP 的 \EFI\TNDOS\ 下， 在 shell 里敲名字就能跑（HELLO 会自动找 HELLO.TNX）。 Drop the resulting .TNX into \EFI\TNDOS\ on the ESP and type its name in the shell -- HELLO finds HELLO.TNX automatically.

编译参数是硬要求The compile flags are not suggestions

-target x86_64-unknown-none 目标三元组：没有操作系统，不链接 libc -ffreestanding freestanding 环境 -fno-builtin 不要把 memcpy 之类换成编译器内建 -fno-stack-protector 没有 __stack_chk_fail 可调 -mno-red-zone <- 最重要 -nostdlib 不链接标准库

-mno-red-zone 是必加的。程序跑在 ring 0，中断和异常使用同一套栈 —— 红区一旦被中断处理程序踩掉，症状是"随机某个局部变量变了"，极难查。 -mno-red-zone is mandatory. The program runs in ring 0 and interrupts and exceptions use the same stack. If an interrupt handler clobbers the red zone, the symptom is "a local variable changed at random", which is brutal to debug.

API 一览The API at a glance

头文件 tndrt.h 里全是扁平函数，没有对象、没有句柄表要自己管。 Everything in tndrt.h is a flat function -- no objects, no handle tables to manage.

控制台 tnd_puts / tnd_putc / tnd_putu / tnd_putx / tnd_printf 环境 tnd_env(name) 句柄 I/O tnd_open / tnd_close / tnd_read / tnd_write / tnd_seek 文件系统 tnd_unlink / tnd_mkdir / tnd_rmdir / tnd_rename / tnd_stat 目录遍历 tnd_findfirst / tnd_findnext / tnd_findclose 屏幕键盘 tnd_cls / tnd_gotoxy / tnd_getkey / tnd_cols / tnd_rows / tnd_setattr 批量原语 tnd_write_cells / tnd_fill / tnd_scroll / tnd_screen 内存时间 tnd_alloc / tnd_free / tnd_ticks 便捷函数 tnd_getline / tnd_readfile / tnd_getch 字符串 tnd_strlen / tnd_strcmp / tnd_stricmp / tnd_memzero / tnd_strncpy

printf 只有一个小抄printf covers a small subset

支持 %s %c %d %u %x %X %p %% 不支持 宽度 / 精度 / 浮点 —— 写 %-28s 或 %6d 会原样打出来 上限 单次格式化结果 512 字节 换行 \n 会自动展开成 \r\n

这条坑实测过：压测程序用了 %-28s，编译通过、运行不报错， 屏幕上就是一堆 %-28s 的字面量。要输出原样字节请用 tnd_write()。 This one bit us for real: a test used %-28s, it compiled, nothing complained, and the screen showed the literal characters %-28s. For verbatim bytes use tnd_write().

写驱动：同一个格式，不同的窗口Drivers: same format, different window

驱动也是 TNX 程序，也从这个入口进 —— 区别只有两点：链接基址和登记自己。 A driver is also a TNX program and enters through the same point. Only two things differ: the link base and registering itself.

tools\build-tnx.ps1 -Source drivers\nvme\nvme.c -Out build\NVME.TNX -ImageBase 0x2000000
程序窗口 0x1000000 一次一个程序 驱动窗口 0x2000000 8 个槽，每个 1 MiB，同一槽重复加载会被拒绝 程序窗口 0x2800000 实际加载基址（见 tnd.h 的 TNX_PROG_BASE）

驱动登记完就留着不走，它的窗口会常驻 —— 程序加载时只清自己的窗口，碰不到驱动。 这就是多窗口的全部意义。语义和 DEVICE= 约定见 docs/DRIVERS.md。 After registering, a driver stays resident -- its window persists. Loading a program only clears the program window, so it cannot touch a driver. That is the whole point of having several windows. See docs/DRIVERS.md for the DEVICE= conventions.

常见坑Traps worth knowing

没有 libc memcpy / strlen 要自己带，或用 tnd_ 系列 没有内存保护 程序崩了系统就崩，运行在 ring 0 8.3 短名 文件系统只解析 8.3，长文件名项跳过 一次一个程序 没有多进程，没有隔离 API 版本 用 tnd_api()->Version 判断能力，别假设

从这里下手Where to start

SDK 仓库里的 examples/ 就是最好的文档 —— hello 覆盖了几乎所有 API， stress 是掺了三个真实开源库（MD5 / AES / inflate）的重负载样例。 The examples/ directory in the SDK is the best documentation: hello exercises almost the whole API, and stress is a heavier sample that links three real open-source libraries (MD5 / AES / inflate).

完整的 API 表结构与版本协商见 TNX 规范， 驱动模型的语义见 docs/DRIVERS.md。 The full API table layout and version negotiation are in the TNX specification; the driver model is described in docs/DRIVERS.md.
